> 素材来源：`奶蛙图片/`（作者提供，共 **27** 张 = 26 张人格素材 + 1 张界面背景图）。本表说明每张素材被指派给哪一型、依据是什么；
> 配图已在 `data/personalities.json` 的 `figure` 字段接线，运行时从 `public/wafrog/` 取图。

> 另有一张 `奶蛙界面背景.png` 不属于任何型号，它是**全站页面背景图**，由 `data/config.json` → `display.background.image` 指定，经 `scripts/make-background.py` 合成后输出到 `public/bg/`，详见 [`../README.md`](../README.md) 的「页面背景」。

## 一、规则

- **一型一图，宁缺毋滥**：只有在气质上明显贴合该型的素材才会被指派；凑不上的一律留空，回退到占位图并显示「该型配图待补」。`npm test` 会强制校验「同一张图不得被两个型号共用」。
- **原图不改**：`奶蛙图片/` 是原始素材库，任何时候都保留。`public/wafrog/` 是**副本**，字节与原图一致。
- **文件名即型号**：`public/wafrog/` 里已启用的图统一命名为 `<型号>人格.jpg`（如 `ESTP人格.jpg`），一眼能看出它属于哪一型；未被启用的素材保留语义名（见第三节）。
- **交换/新增素材只改一处**：把 `public/wafrog/<型号>人格.jpg` 换掉，或改 `data/personalities.json` 里该型的 `figure` 值。**不用改任何代码**。

## 四、怎么改

```bash
# 例：把某型换成另一张素材
# 1) 把图片放进 public/wafrog/，命名为 <型号>人格.jpg（例：ESTP人格.jpg）
# 2) 改 data/personalities.json → items.<型号>.figure = "ESTP人格.jpg"
npm test        # 会校验：文件存在、型号合法、没有被两个型号共用
npm run build   # 改完必须重新构建，再发布
```

## 五、占位图说明

`public/figures/*.svg` 是 `npm run generate-figures` 生成的**原创几何奶蛙**，仅在型号没有专属素材时使用，并在图下方标注「该型配图待补」。**当前 16 型已全部配上专属素材，占位图不再出现**（保留在仓库中，供日后新增型号兜底）。
